# 구성 변경이 개선인지 판정하기

GoalForge 는 실행마다 어떤 구성으로 돌았는지 기록하고 구성별 성공률을 요약해 왔습니다. 그 숫자로 하던 일은 **정렬**이었습니다 — 성공률 높은 순, 같으면 싼 순.

정렬은 **표본을 잘 뽑은 구성을 최고의 구성으로 보여 줍니다.** 그리고 정렬은 진짜 개선과 바뀐 것 없는 구성이 저절로 움직이는 폭을 구별하지 못합니다.

여기의 규칙은 [RRSI: Regularized Recursive Self-Improvement of Agent Harnesses](https://github.com/google-research/rrsi) (Google Research, Apache-2.0, [arXiv:2609.24972](https://arxiv.org/abs/2609.24972)) 의 선택 규칙을 GoalForge 에 맞춘 것입니다. 논문의 주제는 고정된 평가 집합에 대해 에이전트 하네스를 진화시키는 것이고, 그중 **선택 측 정규화** — 노이즈 보정 하한, 추가 비용이 이득으로 값을 치르게 하는 비용 규칙, 노이즈 안에 들어온 변경을 위한 성형 규칙 — 이 여기 적용됩니다. 구현은 우리 것이고 규율은 그쪽 것입니다.

---

## 프로젝트마다 설정합니다

중요한 두 숫자가 프로젝트마다 다릅니다. **바뀐 것 없는 구성이 얼마나 움직이는지**는 그 프로젝트의 평가 사례에 달렸고, **이득이 얼마나 비싸도 되는지**는 그 프로젝트가 무엇을 위한 것인지에 달렸습니다.

```sh
goalforge config selection                      # 현재 정책
goalforge config selection --free-cost 0.05 --cost-per-gain 2.0 --min-trials 20
goalforge config calibrate --label baseline     # 노이즈를 측정한다
goalforge config judge --incumbent baseline     # 판정한다
```

## 노이즈를 먼저 측정합니다

```
$ goalforge config selection
노이즈 대역이 아직 측정되지 않았습니다 — `goalforge config calibrate --label ...` 을 먼저 돌리세요
측정 전에는 어떤 구성 차이도 개선이라고 판정하지 않습니다
```

**측정하지 않은 대역은 대역이 아닙니다.** 추측한 값은 가정에 숫자의 권위를 빌려 주고, 그 가정은 그것이 만들어 낸 판정 안에서 보이지 않습니다. 그래서 기본값에는 대역이 없습니다 — 나머지는 다 방어 가능한 기본값이 있지만 대역만은 이 프로젝트 자신의 측정에서 나와야 합니다.

```
$ goalforge config calibrate --label baseline
노이즈 대역 9.80%p — 사례 10개 · 시행 50회 재표본 추출 (표준오차 4.9%p × 2)
이보다 작은 성공률 차이는 구성이 아니라 측정이 움직인 것입니다
```

대역은 **같은 구성의 반복 시행**에서 나옵니다. 같은 구성이 같은 사례에서 늘 같은 결과를 내지 않고, 성공률은 정확히 그것의 평균입니다.

측정할 수 없으면 거절합니다:

| 상황 | 왜 거절하나 |
| --- | --- |
| 사례별 반복이 1회 | 숫자 하나에는 흔들림이 없습니다. 반복 없이 추정한 대역은 0 이고, **0 인 대역은 모든 차이가 진짜라고 말합니다** — 측정의 권위를 입고서 |
| 모든 반복이 같은 결과 | 이번에 움직이지 않았다는 사실이고, 얼마나 움직이는지에 대해서는 아무것도 보이지 않았습니다 |

반복이 부족한 사례는 **계산에서 빼고** 셉니다. 넣으면 기여할 흔들림이 없는 사례들로 측정된 폭을 0 쪽으로 끌어내립니다.

대역은 **프로젝트마다** 저장됩니다. 한 프로젝트의 측정을 다른 프로젝트의 것으로 읽으면 남의 분산을 내 숫자에 적용하는 것입니다. 정책이 없는 프로젝트는 대역이 없는 정책을 받습니다 — 없는 것을 "보통 쓰는 값" 으로 읽는 기본값은 안 됩니다.

같은 입력은 같은 대역을 냅니다. 판정을 다시 유도할 수 있어야 합니다.

## 판정

```
$ goalforge config judge --incumbent baseline
현재 구성: baseline — 성공률 78.0% · 시행 50회

[v] real      성공률 12.0%p (노이즈 9.8%p 초과) · 비용 +10% (허용 +29%)
[=] tweak     성공률 차이 8.0%p 는 노이즈 9.8%p 안이라 개선이 아닙니다 — 추가 비용 없이 소폭이나마 올라 받아들입니다
[ ] costly    성공률은 16.0%p 올랐지만 비용이 +500% 로 허용치 +37% 를 넘습니다

채택 후보: real (성공률 90.0%)
```

예전 정렬은 `costly` 를 맨 위에 놓았을 것입니다.

| 판정 | 뜻 |
| --- | --- |
| `[v] BETTER` | 이득이 노이즈보다 크고 비용도 값을 치릅니다 |
| `[=] NO_WORSE` | 차이가 노이즈 안이라 **개선이 아니지만**, 더 싸거나 처음 건드리는 구성이라 받아들일 만합니다 |
| `[ ] NOT_SHOWN` | 숫자가 변경을 뒷받침하지 않습니다 |
| `[?] UNJUDGEABLE` | 측정이 아직 아무것도 결정할 수 없습니다 |

`NO_WORSE` 를 따로 두는 이유: **그것은 개선이 아닙니다.** 판정이 어느 쪽인지 말하지 않으면 다음에 읽는 사람이 개선으로 인용합니다.

### 규칙

**하한은 지금까지의 최고 점수에서 노이즈를 뺀 값입니다.** 기존 구성이 아니라 최고 기록에서 재는 이유는, 그렇지 않으면 한 번에 한 걸음씩 조용히 내려갈 수 있기 때문입니다 — 각 걸음은 바로 앞 걸음 대비 노이즈 안이고, 열 걸음 뒤에는 시작한 곳보다 확실히 나빠져 있습니다.

**추가 비용은 측정된 이득으로 값을 치러야 합니다.** 허용치는 `무상분 + 계수 × 이득` 입니다. 진짜 이득이 네 배 비싸다면 그것은 아무도 감당할 수 없는 진짜 이득이고, **진짜가 아닌 이득과는 다른 문제입니다** — 하나는 싸게 만들고 하나는 그만둡니다. 그래서 사유를 구분해 말합니다.

**표본이 작으면 이길 수 없습니다.** 2회 중 2회 통과가 200회 중 190회를 이겼다고 보인 것은 아닙니다. 함께 정렬하면 실패할 기회가 가장 적었던 표본이 이깁니다.

**현재 구성을 정할 수 없으면 거절합니다.**

```
$ goalforge config judge
error: 현재 구성을 정할 수 없습니다 — costly, real, tweak, baseline 가 모두 50회로 같습니다.
       `--incumbent 라벨` 로 지정하세요
```

아래의 모든 판정이 현재 구성 **대비** 비교이므로, 임의로 하나를 고르면 보고서 전체가 무엇을 기준으로 재는지를 조용히 결정해 버립니다.

---

## 아직 안 한 것

RRSI 의 제안 측 정규화 — 어닐링되는 편집 예산, 편집 이력에 조건화된 제안, 정체 시 미시도 구성으로의 유도, 도움이 멈춘 구성의 가지치기 — 는 아직 적용하지 않았습니다. 선택 측이 먼저인 이유는 그것이 없으면 제안이 무엇을 향해 개선되는지 자체가 측정되지 않기 때문입니다.
